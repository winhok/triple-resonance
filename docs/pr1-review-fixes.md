## P1：保护参数失效与新增计划门禁

实际买入成交仍然原子写入成交、数量、现金和费用；若止损/目标缺失、止损不低于入场参考价、
目标不高于入场参考价，或目标不高于止损，则将持仓标记为 `blocked=True`，
并返回/导出 `protection_issues` 说明原因。`plan()` 在计算风险预留前检查所有未平 T 仓，
任一仓位保护不安全即返回 `UNSAFE_PROTECTION`，包括其他股票的新计划。

保护校验采用当前 T 仓均价和最近一次实际买入价，二者均需严格位于止损与目标之间；
部分成交可能使旧保护价失效，因此每次实际买入后重新校验。
这是一条保守的入场保护校验，不是行情报价或止损订单认证；当前 `set-risk` 不将
超越这些参考价的移动保护自动视为有效。

`set-risk` 拒绝失效的修正；有效修正仅解除保护问题，不清掉独立的现金/数量/对账
阻断或已触发的退出锁。对账数量吻合也不能绕过保护校验。旧 JSON 持仓在读取时重新
校验；不重写历史成交。实际卖出仍能登记，全平后不存在该持仓的保护风险预留。
定时器对错误保护发出 `UNSAFE_PROTECTION`，缺少参数时保留 `UNPROTECTED_POSITION`。

## P2：有限的尾盘提醒

每个交易日、每段持仓生命周期最多三阶段，时间跟随 session（含提前收盘）：

| 阶段 | 时间范围 | 事件 |
|---|---|---|
| initial | 收盘前15分钟至前5分钟 | `T_FLATTEN_REQUIRED`，一次 |
| urgent | 收盘前5分钟至收盘 | `T_FLATTEN_REQUIRED`，一次 |
| closed | 收盘时或其后首次检查 | `T_UNFLATTENED_AT_CLOSE`，一次 |

常规日对应15:45、15:55、16:00 ET。重启后只发送当前阶段，不补发已错过的阶段。
事件键由交易日、股票、该仓位入场时间和阶段组成，SQLite 持久化去重；部分卖出不重置
提醒次数。实际全平后停止提醒；后来真实新开的仓位有自己的提醒。收盘后不再反复
发送 `T_FLATTEN_REQUIRED`，下一日未平仓仍由既有隔夜检查处理。
